# API Documentation

Full interactive OpenAPI docs are auto-generated by FastAPI and available at:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Raw schema: `http://localhost:8000/openapi.json`

This document is a written summary of the same endpoints, grouped by page.

All JSON responses that carry a model prediction include a `disclaimer`
field and probabilities that are always strictly between 0 and 1 — the API
is architecturally incapable of returning an exact 0%/100% certainty.

## Dashboard (`/api/dashboard`)

### `GET /api/dashboard/candles`
Query params: `symbol` (default `BTCUSDT`), `limit` (default 200, max 1000).
Returns an array of OHLCV candles ordered oldest → newest for charting.

### `GET /api/dashboard/latest-signal`
Returns the most recently generated signal (or `null` if none yet):
```json
{
  "id": "uuid",
  "generated_at": "2026-08-29T12:34:00Z",
  "action": "BUY",
  "prob_up": 0.6423,
  "prob_down": 0.3577,
  "confidence": 0.2846,
  "price_at_signal": 64213.50,
  "explanation": {"rsi_14": 0.0231, "macd_hist": 0.0187, "...": "..."},
  "disclaimer": "Probabilistic estimate only. Not a guarantee of future price movement."
}
```

### `GET /api/dashboard/positions`
Returns all currently `OPEN` positions.

### `GET /api/dashboard/summary`
Aggregate payload for the whole Dashboard page in one call: latest price,
latest signal, open positions, today's realized PnL, current unrealized
PnL, and whether trading is enabled.

## Model Monitoring (`/api/monitoring`)

### `GET /api/monitoring/current`
Latest monitoring snapshot for the active model: daily/weekly accuracy,
win rate, Sharpe ratio, profit factor, max drawdown, and the calibration
curve (array of `{bucket_mid, predicted, observed, n}`).

### `GET /api/monitoring/history?days=30`
Time series of daily snapshots for trend charts.

---

## Retraining System (`/api/retraining`)

### `GET /api/retraining/jobs?limit=20`
Recent ingestion/retrain job runs with status (`pending|running|success|failed`).

### `GET /api/retraining/models?limit=20`
All trained model versions with training metadata and metrics.

### `GET /api/retraining/models/champion`
The currently selected best model (or `null` if none promoted yet).

### `POST /api/retraining/retrain`
Body: `{"reason": "manual_trigger"}` (optional). Kicks off an async
retrain job (data refresh → feature gen → train → evaluate → possible
promotion) and immediately returns the created job record; poll
`/api/retraining/jobs` for status.

### `POST /api/retraining/models/{model_id}/activate`
Manually promotes a specific model version to be the one serving live
signals (independent of the champion-selection logic — useful for manual
rollback).

## Backtesting (`/api/backtest`)

### `POST /api/backtest/run`
Runs a new backtest using the current champion model over a historical
window. Body:
```json
{
  "period_start": "2026-08-01T00:00:00Z",
  "period_end": "2026-08-29T00:00:00Z",
  "initial_capital": 10000,
  "buy_prob_threshold": 0.60,
  "sell_prob_threshold": 0.60,
  "stop_loss_pct": 0.02,
  "take_profit_pct": 0.04,
  "position_size_pct": 0.10
}
```
Returns equity curve, trade log, monthly returns, and metrics
(`total_return_pct`, `sharpe_ratio`, `max_drawdown_pct`, `win_rate`,
`profit_factor`, trade counts). Requires at least 100 candles in the
requested window and a trained champion model (400 if missing).

### `GET /api/backtest/{backtest_id}`
Fetch a previously run backtest, including its full trade log.

### `GET /api/backtest?limit=10`
List recent backtests (summary only, trade logs omitted for brevity).

## Admin Panel (`/api/admin`)

### `GET /api/admin/settings`
Current risk/threshold configuration (single row).

### `PUT /api/admin/settings`
Partial update — only send the fields you want to change. All numeric
fields are range-validated (e.g. thresholds must be in `[0.5, 0.99]`).
Body example:
```json
{
  "trading_enabled": true,
  "buy_prob_threshold": 0.65,
  "stop_loss_pct": 0.015,
  "updated_by": "jane"
}
```
Every changed field is written to `admin_audit_log` with old/new values.

### `GET /api/admin/audit-log?limit=50`
Recent configuration changes for traceability.

## WebSocket

### `ws://localhost:8000/ws/live`
No subscribe message required — connecting streams both channels
automatically. Message shapes:

```json
{"type": "price", "symbol": "BTCUSDT", "price": 64213.5, "open_time": 1735500000000, "is_closed": false}
```
```json
{
  "type": "signal", "id": "uuid", "action": "HOLD",
  "prob_up": 0.5231, "prob_down": 0.4769, "confidence": 0.0462,
  "price": 64213.5, "explanation": {"...": "..."}, "reasons": ["..."],
  "disclaimer": "...", "generated_at": "2026-08-29T12:34:00Z"
}
```

The frontend's `app/lib/useLiveSocket.ts` hook wraps this connection with
automatic reconnect (3s backoff) and exposes `lastPrice` / `lastSignal` /
`connected` to React components.
